UNIT – III

3.1Microprocessor Systems

A microprocessor is a programmable, clock-driven digital IC that contains the CPU (ALU + control unit + registers) on a single chip. It needs external memory and I/O chips to make a working microprocessor system.
  • ALU – does arithmetic (add, subtract) and logic (AND, OR, compare) operations.
  • Control Unit – fetches & decodes instructions, generates timing/control signals.
  • Registers – fast storage: Accumulator (A), general purpose (B,C,D,E,H,L), Program Counter (PC) holds address of next instruction, Stack Pointer (SP), Flag/status register (Z, C, S, P, AC).
  • Buses – group of parallel wires:
    • Address bus – unidirectional (CPU → memory). 16 lines ⇒ 2¹⁶ = 64 KB addressable.
    • Data bus – bidirectional, width = word size (8-bit in 8085).
    • Control bus – RD, WR, IO/M, ALE, reset, interrupt lines.
  • Memory – ROM/EPROM (program, non-volatile), RAM (data, volatile).
  • I/O ports – interface to keyboard, sensors, displays, actuators (via PPI 8255 etc.).

Fig 1 – Microprocessor system (CPU + memory + I/O on three buses)

Instruction cycle

Fetch (PC → address bus, opcode read from memory) → Decode (CU interprets opcode) → Execute (ALU/register/memory action) → PC incremented → repeat. Time for one instruction = several machine cycles, each = several T-states (clock periods).

Example – 8085: 8-bit data, 16-bit address, 40-pin, 5 interrupts (TRAP, RST 7.5, 6.5, 5.5, INTR), multiplexed AD0–AD7, ~3 MHz clock.

How a microprocessor system works – step by step

  1. On power-up / RESET, the Program Counter is cleared (PC = 0000H), so the CPU always starts from the program stored in ROM at address 0000H.
  2. The CPU puts the PC value on the address bus. An address decoder uses the upper address lines to give a chip-select signal, so only one chip (ROM, RAM or port) responds.
  3. The CPU makes RD̄ low (read). The selected memory places the stored byte (the opcode) on the data bus.
  4. The opcode goes into the instruction register → instruction decoder. The control unit now knows what to do and generates the needed control signals.
  5. If the instruction needs more bytes (data or address), extra memory-read cycles are done. Results go into the accumulator/registers, or are written to memory (WR̄ low) or to an output port (OUT instruction).
  6. PC increments to the next instruction and the cycle repeats – millions of times per second.

Fig 1a – Opcode-fetch machine cycle of 8085 (4 T-states)

Why ALE? In 8085 the lower address and data share the same pins (AD0–AD7) to save pins. During T1 they carry the address; ALE (Address Latch Enable) tells an external latch (74LS373) to hold it, so in T2–T3 the same pins can carry data. This is called bus multiplexing / demultiplexing.

Interface 8 KB ROM and 8 KB RAM to 8085 (64 KB address space).

  • 8 KB = 8192 = 2¹³ ⇒ each chip needs 13 address lines A0–A12.
  • Remaining lines A13, A14, A15 go to a 3-to-8 decoder (74LS138) → 8 chip-selects, each covering one 8 KB block.
  • Output Y0 (A15A14A13 = 000) → ROM: 0000H – 1FFFH. Output Y1 (001) → RAM: 2000H – 3FFFH. Y2…Y7 free for expansion / I/O.
  • The list of which chip sits at which address is called the memory map.

Polling vs interrupts

  • Polling: CPU keeps checking an input in a loop ("is the key pressed?"). Simple, but wastes CPU time and may react late.
  • Interrupt: the device sends a signal on an interrupt pin; CPU finishes the current instruction, saves PC on the stack, jumps to the Interrupt Service Routine (ISR), then returns (RET). Fast response, CPU free otherwise. Used for emergency stop, encoders, timers, serial data.
  • 8085: TRAP is non-maskable (highest priority, used for power failure); RST 7.5, 6.5, 5.5 are maskable vectored; INTR is non-vectored.

3.2Microcontrollers & Applications

A microcontroller (MCU) is a complete computer on a single chip — CPU + ROM/Flash + RAM + I/O ports + timers + ADC + serial interface — designed for embedded control of a dedicated task.

Fig 2 – Inside a microcontroller (everything on one chip)

Popular MCUs: Intel 8051 (8-bit, 4 KB ROM, 128 B RAM, 4 × 8-bit ports P0–P3, 2 timers, 1 UART, 5 interrupts) · Microchip PIC16F877A · Atmel AVR ATmega328 (Arduino UNO) · ARM Cortex-M (STM32).

Applications

  • Washing machine – MCU reads water-level, temperature, door switch; drives valves, heater, drum motor through wash → rinse → spin program.
  • Automobile – ABS, airbag, engine ECU, cruise control.
  • Domestic – microwave oven, AC, camera auto-focus, smart meter.
  • Industrial – temperature/PID controllers, CNC, robots, conveyor control.
  • Medical – infusion pumps, pacemakers, BP monitors.
  • Office – printers, photocopier, ATM, barcode readers.
Always draw the block diagram + a 7-row comparison table. "Applications" questions want 1 example explained in steps (e.g., washing machine: inputs → MCU program → outputs).

Von Neumann vs Harvard architecture

Fig 2a – Von Neumann (PCs, 8085) vs Harvard (8051, PIC, AVR)

In Von Neumann the CPU cannot fetch an instruction and read data at the same time (the Von Neumann bottleneck). Harvard allows both together, so it is faster and suits real-time control – that is why most microcontrollers use it.

8051 microcontroller in detail

  • CPU: 8-bit, accumulator A and register B (for MUL/DIV), 16-bit DPTR (data pointer), PC, SP, PSW (flags CY, AC, OV, P, bank select RS1 RS0).
  • Internal RAM 128 bytes: 00–1FH = 4 register banks (R0–R7 each), 20–2FH = 16 bytes bit-addressable (128 bits), 30–7FH = scratch pad. 80–FFH = Special Function Registers (P0–P3, TMOD, TCON, SCON, SBUF, IE, IP, TH0/TL0, TH1/TL1).
  • 4 KB on-chip ROM; up to 64 KB external program + 64 KB external data memory.
  • Ports: P0 (open drain, also AD0–AD7 – needs pull-ups), P1 (pure I/O), P2 (also A8–A15), P3 (alternate: RXD, TXD, INT0, INT1, T0, T1, WR̄, RD̄).
  • Two 16-bit timers/counters T0, T1 with 4 modes (mode 1 = 16-bit, mode 2 = 8-bit auto-reload, used for baud rate).
  • Full-duplex UART, 5 interrupt sources (INT0, TF0, INT1, TF1, RI/TI) with 2 priority levels.
  • Clock: 12 MHz crystal; one machine cycle = 12 clock periods = 1 µs.

Generate a 1 ms delay using Timer 0, mode 1, with a 12 MHz crystal.

  • Timer increments every machine cycle = 1 µs ⇒ counts needed = 1000 µs / 1 µs = 1000.
  • Timer overflows at 65536, so load = 65536 − 1000 = 64536 = FC18H ⇒ TH0 = FCH, TL0 = 18H.
  • Set TMOD = 01H, start with TR0 = 1, wait until TF0 = 1, then clear TF0 and TR0.

Microcontroller application in detail – temperature controller (oven)

Fig 2b – MCU temperature controller: block diagram and program flowchart (ON-OFF with ±1 °C band)

Why ±1 °C band (hysteresis)? Without it the relay would chatter ON/OFF rapidly around the set point and wear out. T formula: 10-bit ADC, 5 V ref ⇒ 1 count = 4.89 mV; LM35 gives 10 mV/°C ⇒ T = ADC × 4.89/10 = ADC × 0.489 °C.

Choosing a microcontroller

Word size (8/16/32-bit) · speed · Flash & RAM size · number of I/O pins · on-chip peripherals (ADC, PWM, CAN, USB) · power consumption (battery devices) · cost & availability · development tools & community support · operating temperature.

3.3Programmable Logic Controller (PLC)

A PLC is a rugged digital electronic device with programmable memory that stores instructions to implement logic, sequencing, timing, counting and arithmetic functions to control machines and processes (IEC 61131). It replaced hard-wired relay panels.

Advantages: easy reprogramming (no rewiring), compact, reliable in noisy/dusty factories, fault diagnosis, fast, cheap for complex logic, communication with SCADA/HMI.

Basic PLC structure

Fig 3 – Basic PLC structure

  • Processor (CPU) – interprets input signals, executes stored program, sends decisions as output signals.
  • Power supply – converts 230 V AC to low DC (5 V / 24 V) for processor & modules.
  • Memory – ROM (OS/firmware), RAM (user program, data), EEPROM/battery backup.
  • Input/Output modules – the interface; provide opto-isolation and signal level conversion (e.g., 24 V DC/230 V AC → 5 V logic). Output types: relay (AC/DC, slow), transistor (DC, fast), triac (AC).
  • Programming device – enter/edit program, monitor online.
  • Communication interface – connects to other PLCs, HMI, SCADA (Modbus, Profibus, Ethernet/IP).

Input / output processing (scan cycle)

Fig 4 – PLC scan cycle (repeats continuously)

Two ways of handling I/O:

  1. Continuous updating – processor reads each input only when that instruction is met in the program; output updated immediately. Simple but slow for big programs.
  2. Mass I/O copying – all inputs are copied into RAM (input image) at the start of scan, program works on the copy, and all outputs are written together at the end. Faster and consistent – used in most PLCs.

I/O addressing: Mitsubishi X0, X1… (inputs) / Y0, Y1… (outputs) / M (internal relays) · Siemens I0.0 / Q0.0 / M0.0 · Allen-Bradley I:0/1, O:0/1.

Inside an input module (opto-isolation)

Fig 3a – Digital input module: field switch → LED → light → photo-transistor → CPU

  • Sourcing vs sinking: a sourcing (PNP) device supplies +24 V to the input; a sinking (NPN) device connects the input to 0 V. Sensor and module type must match.
  • Each input has a status LED on the module – very useful for fault finding.
  • Analog modules convert 4–20 mA / 0–10 V into numbers (e.g., 12-bit: 0–4095) and vice-versa for outputs.

Types of PLC: Compact / fixed (CPU + I/O + power supply in one box, e.g., up to 40 I/O) and Modular / rack (separate cards slid into a rack; any mix of I/O, hundreds–thousands of points). By size: micro (<32 I/O), small (<256), medium (<1024), large.

Memory organisation (Allen-Bradley style): program files (user ladder) and data files – O0 output image, I1 input image, S2 status, B3 bits (internal relays), T4 timers, C5 counters, R6 control, N7 integers, F8 floats.

Find the scan time: program = 2000 instructions at 0.5 µs each, I/O update = 0.5 ms, housekeeping = 0.5 ms.

Program execution = 2000 × 0.5 µs = 1 ms ⇒ Scan time = 1 + 0.5 + 0.5 = 2 ms.

Meaning: an input pulse shorter than ~2 ms may fall between two input scans and be missed. For fast signals (encoders) use high-speed counter modules or interrupt inputs. Worst-case response time ≈ 2 × scan time.

3.4Ladder Programming

Ladder diagram (LD) is a graphical PLC language that looks like a relay circuit: two vertical power rails, horizontal rungs with contacts (inputs) on the left and a coil (output) on the right.

Fig 5 – Series = AND, parallel = OR, NC contact = NOT

SymbolNameMeaning
—| |—Normally open (NO) contactPasses power when input is ON (1)
—|/|—Normally closed (NC) contactPasses power when input is OFF (0)
—( )—Output coilEnergised if rung is logically true

Rules for drawing ladder

  1. Read left → right, top → bottom (order of scan).
  2. Each rung starts at left rail with input contacts and ends at right rail with one output.
  3. Outputs (coils) are never placed on the left; contacts never on the right of a coil.
  4. A contact can be used many times; an output address normally only once as a coil.
  5. Every input/output is given an address (X0, Y0…).

Steps to write a ladder program for any problem

  1. List all inputs (switches, sensors) and outputs (motors, valves, lamps).
  2. Give each an address (I/O allocation table).
  3. Write the logic as Boolean equations or a truth table / sequence chart.
  4. Draw one rung per output; add latches, interlocks, timers as needed.
  5. Add safety: NC stop/E-stop buttons, interlocks between opposite outputs.
  6. Write instruction list if asked; test (simulate) the program.

Draw the ladder and instruction list for Y = (A + B)·C̄ + D.

LD   X0    ; A
OR   X1    ; A + B
ANI  X2    ; (A + B)·C̄
OR   X3    ; … + D
OUT  Y0

Two-hand safety control of a press: press (Y0) should work only when the operator presses both buttons X0 and X1 (so both hands are away from the die) and the guard switch X2 is closed, and E-stop X3 (NC) is not pressed. ⇒ Y0 = X0 · X1 · X2 · X̄3 – four contacts in series (X3 drawn as NC).

3.5Latching & Internal Relays

Latching (self-holding) keeps an output ON after the momentary input (push button) is released, by putting a contact of the output itself in parallel with the input.

Fig 6 – Start/Stop latch circuit (motor control)

  • Stop button wired as NC for fail-safe: a broken wire stops the motor.
  • SET / RESET (SET/RST, S/R) instructions do the same job: SET Y0 latches, RST Y0 unlatches.

Internal relays (auxiliary relays / markers / flags)

  • Software bits inside PLC memory (M0, M100… or B3:0) that behave like relays but have no physical output terminal.
  • Used to store intermediate results, build complex logic, start several outputs from one condition, and in latch / sequencing / shift-register programs.
  • Battery-backed (retentive) relays keep their state during power failure — so the process resumes from the same step.

Fig 6a – Latching with SET / RESET instructions

Forward / reverse motor with interlocking

Fig 6b – Forward/reverse control: latch + stop + interlock

Why interlock? If forward and reverse contactors close together, two supply phases short-circuit. The NC contact of the opposite output prevents this (software interlock); in practice a mechanical/electrical interlock is also added on the contactors.

Using internal relays – example

Condition "machine ready" = guard closed (X0) AND air pressure OK (X1) AND no fault (X2 NC). This is needed in many rungs, so store it once: X0 · X1 · X̄2 → M0. Then use contact M0 in every rung: M0 → Y0 (green lamp), M0 · Start → Y1 (motor), M0 · X3 → Y2 (clamp). Program is shorter, clearer and easier to change.

Edge (one-shot) contacts: PLS / PLF (Mitsubishi), ONS (A-B), P_TRIG – give an output for exactly one scan on the rising / falling edge of an input. Used to count events and to make a single push button toggle a light ON/OFF.

3.6Sequencing

Many machines run actions in a fixed order (e.g., drilling: clamp → drill down → drill up → unclamp). Sequence is controlled using limit switches, internal relays, timers, or a sequencer (drum) instruction.

Example – two pneumatic cylinders A, B: sequence A+ B+ A− B− (+ = extend, − = retract). Limit switches: a0/a1 (A retracted/extended), b0/b1.

Fig 7 – Displacement–step diagram for A+ B+ A− B−

Logic: A+ = Start · a0 · b0  |  B+ = a1  |  A− = b1  |  B− = a0 (after A−). Each step is stored in an internal relay (M1…M4) which is latched and the previous one reset — this avoids two signals conflicting (signal overlap).

Ladder program (single-solenoid, spring-return valves YA for cylinder A and YB for B):

Fig 7a – Ladder for the A+ B+ A− B− sequence

Sequencing with timers – traffic lights

Sequence: RED 30 s → GREEN 25 s → AMBER 5 s → repeat (timer base 0.1 s).

Fig 7b – Traffic lights: timing chart and cascaded-timer ladder

How it works: T0 times the red period; when T0 is done it starts T1 (green); T1 done starts T2 (amber). When T2 finishes, its NC contact breaks rung 1, resetting T0 → T1 → T2, and the cycle starts again with red. Outputs are decided by which timers are done: RED = T̄0, GREEN = T0·T̄1, AMBER = T1.

3.7Timers & Counters

Timers

  • TON – On-delay timer: output turns ON after preset time once input stays ON. (Most common.)
  • TOF – Off-delay timer: output ON immediately, turns OFF preset time after input goes OFF (e.g., cooling fan runs after motor stops).
  • RTO – Retentive timer: accumulates time over several ON periods; needs a RESET.
  • Pulse timer (TP): gives a fixed-width pulse.
  • Time = Preset (PV/PRE) × time base (10 ms, 100 ms, 1 s). Accumulated value = ACC/ET.

Fig 8 – On-delay timer: ladder + timing diagram

Counters

  • CTU – Up counter: counts rising edges; when count = preset, counter contact closes.
  • CTD – Down counter: counts down from preset to 0.
  • CTUD – Up/down counter (e.g., cars entering/leaving a car park).
  • Always needs a RESET input to bring the count back to zero.

Fig 9 – Up counter: packing 10 items per box

Timing diagrams – OFF-delay and retentive timers

Fig 9a – TOF: output stays ON for preset time after input goes OFF · RTO: time adds up over several ON periods, cleared only by RESET

Preset value = required time ÷ time base. 25 s with 0.1 s base ⇒ K = 25/0.1 = 250. 2.5 s with 10 ms base ⇒ K = 250.

Long delays (cascading): if one timer max = 3276.7 s, a 2-hour delay (7200 s) can be made by T0 = 3600 s, and T0 done starts T1 = 3600 s. Or use a 60 s timer driving a counter set to 120.

Up/down counter – car park

Entry sensor X0 → count up; exit sensor X1 → count down; preset = number of spaces (100). When count = 100, counter output C0 turns ON → "FULL" sign (Y0) lights and entry barrier is not opened. Each car leaving reduces the count, so the sign goes off.

3.8Shift Registers

A shift register is a group of internal relays (usually 8 or 16 bits, e.g., M100–M107) in which each bit's status is moved one place along each time a shift (clock) pulse arrives. Used to track items on a conveyor.

Three inputs: OUT (data in – value entered into first bit), SFT (shift pulse) and RST (clear all bits).

Fig 10 – 8-bit shift register before and after a shift

Application – rejecting faulty bottles: inspection sensor at station 1 puts "1" (faulty) into M100; each bottle movement gives a shift pulse; when the "1" reaches M104 (the reject station) it energises the reject solenoid.

Types: bit shift left (BSL) / bit shift right (BSR), word shift, FIFO (first-in-first-out stack). Shift registers are used for tracking parts on conveyors, sequencing (a single "1" moving along the register switches outputs one after another) and serial data handling.

3.9Master Control & Jump Controls

Fig 11 – Left: master control relay (MCR) zone · Right: jump (JMP / LBL)

  • Master control relay (MCR): switches a whole block of rungs on/off together. If the MCR rung is false, all non-retentive outputs inside the zone are turned OFF. Used for emergency/section shutdown. Zone ends with MCR END (MCE).
  • Jump (JMP) & Label (LBL): when the jump condition is true, the PLC skips rungs up to the label. Outputs in the skipped section are held in their last state (not turned off). Saves scan time; used to choose between two program sections (e.g., manual / auto mode).
  • Difference: MCR → outputs OFF · JMP → outputs frozen.

Manual / Auto mode selection using jumps (selector switch X0: ON = auto).

Rung 1:  X0 ──| |──────────── JMP L1   ; auto → skip manual section
         ... manual rungs (jog buttons drive motors directly) ...
Rung n:  LBL L1
Rung n+1: X0 ──|/|─────────── JMP L2   ; manual → skip auto section
         ... auto rungs (sequence, timers, counters) ...
Rung m:  LBL L2
         ... common rungs (alarms, lamps) – always scanned ...

Only one section is scanned at a time ⇒ shorter scan, and manual and auto logic can never fight over the same output.

  • Subroutines (CALL / RET, JSR / SBR): a block of rungs written once and called when needed (e.g., a recipe calculation).
  • Note: MCR is a software function – an emergency stop must still be hard-wired to cut power, because a PLC fault could stop the MCR from working.

3.10Code Conversion & Data Handling

Code conversion

Field devices often use BCD (thumbwheel switches, 7-segment displays) while the PLC works in binary. PLCs provide BIN (BCD → binary) and BCD (binary → BCD) instructions; also Gray code (from absolute encoders) and ASCII.

DecimalBinaryBCDGray
501010000 01010111
910010000 10011101
1211000001 00101010
590011 10110101 1001—

Worked: 59 → BCD: 5 = 0101, 9 = 1001 ⇒ 0101 1001.   Binary → Gray: Gn = Bn, Gi = Bi+1 ⊕ Bi (e.g., 1100 → 1010). Gray code changes only 1 bit between steps ⇒ no false readings in encoders.

Data handling

PLCs store 16-bit words in data registers (D0, D1…; N7:0). Instructions:

  • Move: MOV / MOVE source → destination (copy a value, e.g., load new timer preset).
  • Compare: EQU (=), NEQ (≠), GRT (>), LES (<), GEQ, LEQ – contact closes if true. E.g., if temperature D0 > 80 then turn heater OFF.
  • Arithmetic: ADD, SUB, MUL, DIV, SQR.
  • Logical: word AND, OR, XOR, NOT; masking bits.
  • Block transfer / FIFO / table functions for recipes & logging; analog inputs read through ADC modules as numbers (0–4095).

BCD → binary: 0101 1001 (BCD) = 5 × 10 + 9 = 59 = 0011 1011₂.

Binary → BCD: 147 = 1001 0011₂ → split decimal digits 1, 4, 7 ⇒ 0001 0100 0111.

Gray → binary: Bn = Gn, then Bi = Bi+1 ⊕ Gi. Gray 1010 → B3=1, B2=1⊕0=1, B1=1⊕1=0, B0=0⊕0=0 ⇒ 1100 = 12.

Fig 11a – Comparison instructions act like contacts: closed when the comparison is true

Scaling an analog input: a 12-bit analog module reads 0–4095 for 0–150 °C. Temperature = raw × 150 / 4095. Raw = 2730 ⇒ T = 2730 × 150 / 4095 = 100 °C. In ladder: MUL D0 K150 D1 then DIV D1 K4095 D2 (multiply first so the integer division doesn't lose accuracy).

MOV example: a machine fills two bottle sizes. Selector X5 ON → MOV K80 D10 (8 s), X5 OFF → MOV K50 D10 (5 s); filling timer T0 uses D10 as its preset.

3.11Selection of a PLC

  1. Number of I/O points required (+ 20% spare for expansion).
  2. Type of I/O – digital/analog, AC/DC, voltage & current levels, relay vs transistor outputs, special modules (high-speed counter, PID, stepper).
  3. Memory size needed for program & data.
  4. Speed – scan time required by process.
  5. Instruction set / functions – timers, counters, maths, PID, shift registers.
  6. Communication – Ethernet, Modbus, Profibus, HMI/SCADA networking.
  7. Environment – temperature, humidity, vibration, dust, EMI.
  8. Type – compact/fixed (small machines) vs modular/rack (large plants).
  9. Cost, vendor support, software, programming language (IEC 61131-3: LD, FBD, ST, IL, SFC).
Remember the IEC 61131-3 languages as "L-F-S-I-S": Ladder, Function block, Structured text, Instruction list, Sequential function chart.

Select a PLC for a packing machine with: 18 push buttons/sensors (24 V DC), 6 solenoid valves (24 V DC), 4 motor contactors (230 V AC coil), 2 lamps, 2 temperature transmitters (4–20 mA), and an HMI touch screen.

  • Digital inputs: 18 + 20% spare ≈ 22 ⇒ choose 24 DI (24 V DC, sink/source).
  • Digital outputs: 12 + 20% ≈ 15 ⇒ 16 DO, relay type (because AC contactor coils + DC valves).
  • Analog: 2-channel 4–20 mA input module, 12-bit.
  • Functions: timers, counters, compare, maths – all standard. Memory ≈ 4–8 k steps.
  • Communication: Ethernet port for HMI.

4.1AI Inclusion in Mechatronics

Classic mechatronics = mechanics + electronics + control + computing. Adding Artificial Intelligence makes the system able to perceive, learn, decide and adapt instead of only following fixed rules — "intelligent mechatronic systems".

Fig 12 – Where AI sits inside a mechatronic loop

AI techniques used

  • Machine learning – regression/classification from sensor data.
  • Computer vision (CNN) – object detection, quality inspection, pick-point finding.
  • Fuzzy logic control – rules like "IF temp is high THEN fan is fast" (washing machines, ACs).
  • Neural-network control – learns nonlinear plant models.
  • Reinforcement learning – robot learns by trial & reward.

Applications

  • Predictive maintenance (vibration analysis → predict bearing failure).
  • Autonomous vehicles / AGVs – path planning, obstacle avoidance (SLAM).
  • Smart robots – adaptive gripping, human-robot collaboration.
  • Self-tuning controllers, anomaly/fault detection.
  • Edge AI / TinyML – models running on MCU itself.

Benefits: adaptability, higher accuracy, less downtime, handles uncertainty. Challenges: needs large data, high compute, explainability, safety certification, real-time limits.

Fuzzy logic controller in detail

Normal (crisp) logic says a value is either "hot" (1) or "not hot" (0). Fuzzy logic allows partial membership between 0 and 1 (e.g., 23 °C is 0.7 "warm" and 0.3 "hot"), just like human reasoning. Very useful when an exact mathematical model of the plant is not available.

Fig 12a – Fuzzy controller structure and triangular membership functions

Fan speed control. Rules: IF cold THEN slow (20%); IF warm THEN medium (50%); IF hot THEN fast (90%).

At T = 23 °C: μcold = 0, μwarm = (30 − 23)/10 = 0.7, μhot = (23 − 20)/10 = 0.3.

Defuzzify (weighted average / centroid): speed = (0.7 × 50 + 0.3 × 90) / (0.7 + 0.3) = (35 + 27) / 1 = 62 %.

So the fan smoothly speeds up as temperature rises – no sudden jumps like ON/OFF control.

Artificial neural network (ANN) – basic neuron

Fig 12b – A neuron: weighted sum of inputs + bias, passed through an activation function (sigmoid, ReLU)

Many neurons in layers (input → hidden → output) form a network. Training = adjusting weights using example data (back-propagation) so the error between predicted and actual output becomes small. In mechatronics ANNs are used for nonlinear system modelling, inverse kinematics of robots, adaptive control and fault classification.

Predictive maintenance using ML – steps

  1. Data collection: accelerometer (vibration), temperature, motor current, acoustic sensors on a machine.
  2. Signal conditioning & DAQ at high sampling rate.
  3. Feature extraction: RMS, peak, kurtosis, FFT frequency peaks (bearing defect frequencies).
  4. Training: classify "normal / faulty", or predict Remaining Useful Life (RUL) from historical failure data.
  5. Deployment on an edge device or cloud; alerts sent to maintenance team before breakdown.

4.2Signal Conditioning & Data Acquisition

Signal conditioning = processing the raw sensor output so that it becomes suitable for the next stage (ADC / controller): right level, clean, safe and linear.

Functions of signal conditioning

  1. Protection – against high voltage/current (zener diode, fuse, current-limiting resistor, opto-isolator).
  2. Amplification – mV signals (thermocouple, strain gauge) → volts, using op-amps.
  3. Filtering – remove noise: low-pass, high-pass, band-pass, notch (50 Hz mains).
  4. Conversion – resistance → voltage (Wheatstone bridge), current 4–20 mA → voltage, analog ↔ digital.
  5. Isolation – optical/transformer isolation between sensor and controller.
  6. Linearisation – correct nonlinear sensor output (look-up table/software).

Fig 13 – Inverting op-amp amplifier (most asked signal-conditioning circuit)

Derivation of inverting gain. Ideal op-amp: infinite gain and input resistance ⇒ (i) no current enters the inputs, (ii) the two inputs are at the same voltage. + input is grounded ⇒ − input is also at 0 V (virtual earth).

Current through R1: I = (Vin − 0)/R1. Same current flows through Rf (none enters op-amp): I = (0 − Vout)/Rf.

⇒ Vin/R1 = −Vout/Rf ⇒ Vout/Vin = −Rf/R1

Numerical: R1 = 1 kΩ, Rf = 100 kΩ, Vin = 20 mV ⇒ gain = −100 ⇒ Vout = −2 V.

Wheatstone bridge (resistance → voltage)

Fig 13a – Wheatstone bridge converts the small resistance change of a strain gauge / RTD into a voltage

Strain gauge R = 120 Ω, G = 2, strain ε = 1000 µε (0.001), Vs = 10 V.

ΔR = G·ε·R = 2 × 0.001 × 120 = 0.24 Ω ⇒ Vo = 10 × 0.24 / (4 × 120) = 5 mV.

To feed a 0–5 V ADC at full scale (say 5 mV = full load) we need gain ≈ 1000 ⇒ use an instrumentation amplifier.

Filtering

Fig 13b – RC low-pass filter and its response

  • Cut-off frequency fc = 1 / (2πRC). Example: R = 10 kΩ, C = 0.1 µF ⇒ fc = 1/(2π × 10⁴ × 10⁻⁷) = 159 Hz.
  • Low-pass removes high-frequency noise (and works as anti-aliasing filter); high-pass removes DC drift; band-pass keeps a band (vibration analysis); notch removes 50 Hz mains hum.
  • Passive filters (R, L, C) vs active filters (with op-amp – can also amplify, no loading).

4–20 mA current loop: industrial standard for sending sensor signals long distances. Current is not affected by wire resistance; "live zero" (4 mA) means 0 mA ⇒ broken wire can be detected. A 250 Ω resistor converts it to 1–5 V for the ADC.

Data Acquisition System (DAQ)

DAQ = the process of measuring physical quantities with sensors, conditioning them, converting to digital form and storing/processing them in a computer.

Fig 14 – Data acquisition system

  • Multiplexer – selects one of many sensor channels at a time to share one ADC.
  • Sample & hold – freezes the voltage while ADC converts.
  • ADC types – successive approximation (common), flash (fastest), dual-slope (accurate, slow), sigma-delta.
  • Sampling theorem (Nyquist): fs ≥ 2 fmax – otherwise aliasing. Use an anti-aliasing low-pass filter.
  • Resolution: Δ V = Vref / 2ⁿ   e.g., 10-bit, 5 V ⇒ 5/1024 = 4.88 mV; 12-bit ⇒ 1.22 mV.
  • DAQ board specs: number of channels, sampling rate, resolution, input range, accuracy.

Successive-approximation ADC – how it converts

It works like a binary search: starting from the MSB, each bit is set to 1, an internal DAC converts the guess to a voltage, and a comparator checks if the guess is above Vin. If above, that bit is cleared to 0. An n-bit conversion takes n steps.

4-bit SAR ADC, Vref = 8 V (1 LSB = 8/16 = 0.5 V), Vin = 5.3 V.

Designing the conditioning for a thermocouple: 40 µV/°C, range 0–500 °C, 10-bit ADC with 0–5 V input.

  • Max thermocouple output = 500 × 40 µV = 20 mV.
  • Gain needed = 5 V / 20 mV = 250 (instrumentation amplifier).
  • Resolution = 500 °C / 1024 = 0.49 °C per count.
  • Temperature changes slowly (< 1 Hz) ⇒ low-pass filter at ~10 Hz removes noise; sampling at 10–20 Hz is enough. Cold-junction compensation also needed.

DAC (digital → analog) for outputs: R-2R ladder or weighted resistor type. Vout = Vref × D / 2ⁿ – 8-bit, Vref 5 V, D = 128 ⇒ 2.5 V.

Sampling in practice: theory says fs ≥ 2 fmax; in practice 5–10 × fmax is used. Example: vibration up to 1 kHz ⇒ sample at 5–10 kHz.

4.4Embedded Firmware Architecture

Firmware is the software permanently stored in the non-volatile (Flash) memory of an embedded device that directly controls its hardware. Its architecture is the way that code is organised into layers and modules.

Fig 16 – Layered firmware architecture

Firmware design models

  1. Super loop (bare-metal): init(); while(1){ read(); compute(); write(); } – simple, cheap; but response time depends on loop length, no priorities.
  2. Interrupt-driven (foreground/background): ISRs handle urgent events, main loop does the rest.
  3. RTOS-based: work split into prioritised tasks; scheduler guarantees deadlines – used for complex & safety-critical systems.
  4. Event-driven / state machine: system modelled as states + transitions (good for sequences).

Key parts: bootloader (start-up, firmware update/OTA), HAL (makes code portable across chips), drivers, watchdog timer, memory map (Flash, RAM, stack, heap).

Super-loop

int main(void){
  init_hw();          // clocks, GPIO, ADC
  while(1){           // forever
    read_sensors();
    compute_control();
    drive_outputs();
    kick_watchdog();
  }
}

Interrupt-driven

volatile int flag = 0;
void TIMER_ISR(void){  // every 1 ms
  flag = 1;            // keep ISR short
}
int main(void){
  init_hw();
  while(1){
    if(flag){ flag=0; control_loop(); }
    background_tasks();   // display etc.
  }
}

Fig 16a – Typical MCU memory map

Boot sequence

  1. Reset → CPU reads the reset vector from the vector table.
  2. Start-up code: set stack pointer, configure clocks, copy .data from Flash to RAM, clear .bss.
  3. Bootloader checks if new firmware is waiting (UART/USB/OTA) and verifies it with a CRC/signature; otherwise jumps to the application.
  4. main(): initialise HAL and drivers, create RTOS tasks, start the scheduler.

Watchdog timer: a hardware counter that resets the MCU if the software does not "kick" (refresh) it in time — recovers the system automatically from a hang. Development flow: write C/C++ → compile & link → .hex/.bin → flash via JTAG/SWD → debug with breakpoints. Good practice: modular layers, MISRA-C coding rules, static analysis, version control, dual-bank OTA updates with rollback.

4.5RTOS for Safety-Critical Systems

A Real-Time Operating System (RTOS) is an OS that guarantees a task's response within a fixed, known time (deterministic). Correctness depends on both the logical result and the time at which it is produced.
  • Hard real-time – missing a deadline = system failure (airbag, ABS, pacemaker, flight control).
  • Soft real-time – occasional miss only degrades quality (video streaming).
  • Safety-critical system – failure can cause death, injury or major damage.

Fig 17 – Task states in an RTOS

Key RTOS concepts

  • Task / thread – independent function with its own stack and priority.
  • Pre-emptive priority scheduling – highest-priority ready task always runs. Rate Monotonic: shorter period ⇒ higher priority. EDF: earliest deadline first. Round-robin for equal priority.
  • Inter-task communication – queues, mailboxes, event flags.
  • Semaphore & mutex – protect shared resources (critical sections).
  • Priority inversion – high task waits for a resource held by a low task while a medium task runs (Mars Pathfinder 1997 bug). Fix: priority inheritance / priority ceiling.
  • Low interrupt latency & context-switch time, small memory footprint.

Safety features needed

  • Determinism & bounded worst-case execution time (WCET).
  • Watchdog timer – resets system if software hangs.
  • Memory protection (MPU) – one task can't corrupt another.
  • Spatial & temporal partitioning (ARINC 653).
  • Redundancy, fail-safe states, error detection (CRC, ECC).
  • Certified to standards: IEC 61508 (SIL 1–4, industrial), ISO 26262 (ASIL A–D, cars), DO-178C (aircraft), IEC 62304 (medical).
  • Examples: FreeRTOS / SafeRTOS, VxWorks, QNX, INTEGRITY, Zephyr.
GPOS vs RTOS: GPOS (Windows/Linux) maximises throughput & fairness; RTOS maximises predictability. Write this line in every RTOS answer.

Priority inversion – explained with a timeline

Fig 17a – Priority inversion: a medium task indirectly delays the high-priority task

Fix – priority inheritance: when H waits for R held by L, L temporarily gets H's priority, so M cannot pre-empt it; L finishes quickly, frees R, and H runs at time 4 instead of 9. Priority ceiling: any task taking R immediately gets the highest priority of all tasks that may use R.

Rate-monotonic scheduling (RMS) – schedulability test

Periodic tasks with compute time Ci and period Ti. CPU utilisation U = Σ Ci/Ti. Under RMS all deadlines are guaranteed if

U ≤ n (21/n − 1)   (n = 1: 1.0, n = 2: 0.828, n = 3: 0.780, n → ∞: 0.693)

T1: C = 1, T = 3 · T2: C = 2, T = 5. ⇒ U = 1/3 + 2/5 = 0.733 ≤ 0.828 ⇒ schedulable. T1 has the shorter period so it gets higher priority.

4.6Building Physics-Accurate CAD Models in Simulation

Before building hardware, mechatronic engineers create a virtual prototype — a CAD model that also has correct physics (mass, inertia, friction, joints, motor limits) — and test controllers on it in a simulator. When it stays linked to the real machine with live data it becomes a digital twin.

Fig 18 – Workflow: CAD → physics model → simulation → validation

  • Accurate parameters: density/material, centre of gravity, moments of inertia, stiffness, gear ratios, motor torque–speed curves, sensor noise.
  • Physics engines: ODE, Bullet, MuJoCo, PhysX; tools – MATLAB Simulink/Simscape Multibody, Gazebo/ROS, CoppeliaSim, MSC Adams, ANSYS (FEA/CFD).
  • Co-simulation: mechanical model + electrical model + control software together (Model-in-the-loop → Software-in-the-loop → Hardware-in-the-loop).
  • Benefits: fewer physical prototypes, lower cost & time, safe testing of failures, controller tuning, training data for AI (sim-to-real).
  • Limits: model only as good as its parameters ("reality gap"), heavy computation.

The physics the simulator solves

For a multi-body system (robot arm) the simulator solves the equation of motion at every time step:

M(q)·q̈ + C(q, q̇)·q̇ + G(q) = τ

M = mass/inertia matrix (from CAD), C = Coriolis & centrifugal terms, G = gravity torques, τ = motor torques, q = joint angles. If the CAD mass or inertia values are wrong, the simulated motor torque and controller tuning will be wrong too – that is why physics-accurate models matter.

Aluminium link (ρ = 2700 kg/m³), 0.4 m × 0.04 m × 0.02 m, rotating about one end in a vertical plane.

  • Mass m = 2700 × 0.4 × 0.04 × 0.02 = 0.864 kg (CAD calculates this from material).
  • Inertia about end I = mL²/3 = 0.864 × 0.16 / 3 = 0.046 kg·m².
  • Torque to accelerate at α = 10 rad/s² while horizontal: τ = Iα + mg(L/2) = 0.46 + 0.864 × 9.81 × 0.2 = 0.46 + 1.70 = 2.16 N·m.
  • With safety factor 1.5 ⇒ choose a motor + gearbox giving ≥ 3.2 N·m. The simulation checks this before buying parts.

Line-following control of an AGV

An array of IR / magnetic sensors under the AGV measures how far the vehicle is from the line → error e. A PID controller gives a correction u: vL = v₀ − u,   vR = v₀ + u. If the AGV drifts right of the line, the right wheel speeds up and the left slows, turning it back.

v₀ = 0.5 m/s, u = 0.1 m/s, wheel separation L = 0.4 m ⇒ vL = 0.4, vR = 0.6 m/s ⇒ v = 0.5 m/s, ω = (0.6 − 0.4)/0.4 = 0.5 rad/s (turning left). Turning radius R = v/ω = 1 m.

  1. Barrier is down; down-limit X3 is pressed (so the lower rung can't run).
  2. Driver inserts coin/ticket → X0 closes momentarily → Y0 energises and latches through its own contact.
  3. Motor raises the arm. When fully up, up-limit X1 (NC in rung) opens → Y0 drops out → motor stops with the arm held up.
  4. Car drives through; the inductive loop / IR beam X2 detects it has passed → Y1 energises and latches.
  5. Motor runs in reverse and lowers the arm until down-limit X3 opens → Y1 drops out. System ready for next car.

Safety improvements: a presence sensor under the arm (X4, NC in the lower rung) stops the arm coming down on a car; a time-out timer gives an alarm if a limit switch is not reached (motor jammed); manual override key for power failure.

Mechatronic elements: sensors (coin validator, limit switches, loop detector), controller (PLC/MCU), actuator (geared DC motor or hydraulic/pneumatic cylinder), mechanism (pivoted arm with counterweight to reduce motor torque).

(d) Engine management system (EMS)

Electronic control of a car engine by an ECU (Engine Control Unit) to get the best power, fuel economy and lowest emissions.

Fig 23 – Engine management system

  • Fuel control: ECU computes injector pulse width from engine speed (crank sensor) and air mass (MAF/MAP); corrected by coolant temp, throttle and O₂ sensor feedback to keep air–fuel ratio at stoichiometric 14.7 : 1 (λ = 1) for the catalytic converter.
  • Ignition control: spark timing (advance) from 3-D map of speed & load; retarded if knock sensor detects detonation.
  • Idle speed, EGR, variable valve timing, OBD-II diagnostics (fault codes, check-engine lamp).
  • Advantages over carburettor: better mileage, lower emissions (BS-VI), smooth start in cold, self-diagnosis.

Closed-loop lambda control – how it works

  • The O₂ sensor in the exhaust gives ~0.8–0.9 V when rich (too much fuel, little O₂ left) and ~0.1 V when lean (excess O₂).
  • ECU reads it: rich → shortens injector pulse; lean → lengthens it. The mixture keeps oscillating slightly around λ = 1, which is exactly what the 3-way catalytic converter needs to clean CO, HC and NOx together.
  • During cold start and full throttle, the ECU runs in open loop using stored maps (sensor not hot / extra power needed).

Injector pulse width. 4-cylinder, 4-stroke engine at 3000 rpm, MAF sensor reads 20 g/s of air, injector flow rate 2 g/s, target AFR 14.7.

  • Each cylinder takes air once every 2 revolutions ⇒ intake events = 4 × 3000 / (60 × 2) = 100 per second.
  • Air per intake = 20 / 100 = 0.2 g ⇒ fuel needed = 0.2 / 14.7 = 0.0136 g.
  • Pulse width = 0.0136 / 2 = 0.0068 s = 6.8 ms (plus a small dead-time for injector opening).

Inside the ECU: input conditioning (filters, ADC, crank-signal shaping) → 32-bit MCU running an RTOS (crank-synchronous tasks have highest priority) → power drivers for injectors and coils → CAN bus to other ECUs (ABS, transmission, dashboard). Calibration maps are stored in Flash and tuned on an engine dyno.
