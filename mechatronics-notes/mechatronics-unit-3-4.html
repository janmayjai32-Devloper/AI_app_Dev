UNIT – III

3.1Microprocessor Systems

A microprocessor is a programmable, clock-driven digital IC that contains the CPU (ALU + control unit + registers) on a single chip. It needs external memory and I/O chips to make a working microprocessor system.
  • ALU – does arithmetic (add, subtract) and logic (AND, OR, compare) operations.
  • Control Unit – fetches & decodes instructions, generates timing/control signals.
  • Registers – fast storage: Accumulator (A), general purpose (B,C,D,E,H,L), Program Counter (PC) holds address of next instruction, Stack Pointer (SP), Flag/status register (Z, C, S, P, AC).
  • Buses – group of parallel wires:
    • Address bus – unidirectional (CPU → memory). 16 lines ⇒ 2¹⁶ = 64 KB addressable.
    • Data bus – bidirectional, width = word size (8-bit in 8085).
    • Control bus – RD, WR, IO/M, ALE, reset, interrupt lines.
  • Memory – ROM/EPROM (program, non-volatile), RAM (data, volatile).
  • I/O ports – interface to keyboard, sensors, displays, actuators (via PPI 8255 etc.).

Fig 1 – Microprocessor system (CPU + memory + I/O on three buses)

Instruction cycle

Fetch (PC → address bus, opcode read from memory) → Decode (CU interprets opcode) → Execute (ALU/register/memory action) → PC incremented → repeat. Time for one instruction = several machine cycles, each = several T-states (clock periods).

Example – 8085: 8-bit data, 16-bit address, 40-pin, 5 interrupts (TRAP, RST 7.5, 6.5, 5.5, INTR), multiplexed AD0–AD7, ~3 MHz clock.

3.2Microcontrollers & Applications

A microcontroller (MCU) is a complete computer on a single chip — CPU + ROM/Flash + RAM + I/O ports + timers + ADC + serial interface — designed for embedded control of a dedicated task.

Fig 2 – Inside a microcontroller (everything on one chip)

Popular MCUs: Intel 8051 (8-bit, 4 KB ROM, 128 B RAM, 4 × 8-bit ports P0–P3, 2 timers, 1 UART, 5 interrupts) · Microchip PIC16F877A · Atmel AVR ATmega328 (Arduino UNO) · ARM Cortex-M (STM32).

Microprocessor vs Microcontroller

ArchitectureMostly Von Neumann (shared bus)Mostly Harvard (separate program & data memory)

Example8085, 8086, Intel Core i78051, PIC, AVR, STM32

Applications

  • Washing machine – MCU reads water-level, temperature, door switch; drives valves, heater, drum motor through wash → rinse → spin program.
  • Automobile – ABS, airbag, engine ECU, cruise control.
  • Domestic – microwave oven, AC, camera auto-focus, smart meter.
  • Industrial – temperature/PID controllers, CNC, robots, conveyor control.
  • Medical – infusion pumps, pacemakers, BP monitors.
  • Office – printers, photocopier, ATM, barcode readers.
Always draw the block diagram + a 7-row comparison table. "Applications" questions want 1 example explained in steps (e.g., washing machine: inputs → MCU program → outputs).

3.3Programmable Logic Controller (PLC)

A PLC is a rugged digital electronic device with programmable memory that stores instructions to implement logic, sequencing, timing, counting and arithmetic functions to control machines and processes (IEC 61131). It replaced hard-wired relay panels.

Advantages: easy reprogramming (no rewiring), compact, reliable in noisy/dusty factories, fault diagnosis, fast, cheap for complex logic, communication with SCADA/HMI.

Basic PLC structure

Fig 3 – Basic PLC structure

  • Processor (CPU) – interprets input signals, executes stored program, sends decisions as output signals.
  • Power supply – converts 230 V AC to low DC (5 V / 24 V) for processor & modules.
  • Memory – ROM (OS/firmware), RAM (user program, data), EEPROM/battery backup.
  • Input/Output modules – the interface; provide opto-isolation and signal level conversion (e.g., 24 V DC/230 V AC → 5 V logic). Output types: relay (AC/DC, slow), transistor (DC, fast), triac (AC).
  • Programming device – enter/edit program, monitor online.
  • Communication interface – connects to other PLCs, HMI, SCADA (Modbus, Profibus, Ethernet/IP).

Input / output processing (scan cycle)

Fig 4 – PLC scan cycle (repeats continuously)

Two ways of handling I/O:

  1. Continuous updating – processor reads each input only when that instruction is met in the program; output updated immediately. Simple but slow for big programs.
  2. Mass I/O copying – all inputs are copied into RAM (input image) at the start of scan, program works on the copy, and all outputs are written together at the end. Faster and consistent – used in most PLCs.

I/O addressing: Mitsubishi X0, X1… (inputs) / Y0, Y1… (outputs) / M (internal relays) · Siemens I0.0 / Q0.0 / M0.0 · Allen-Bradley I:0/1, O:0/1.

3.4Ladder Programming

Ladder diagram (LD) is a graphical PLC language that looks like a relay circuit: two vertical power rails, horizontal rungs with contacts (inputs) on the left and a coil (output) on the right.

Fig 5 – Series = AND, parallel = OR, NC contact = NOT

SymbolNameMeaning
—| |—Normally open (NO) contactPasses power when input is ON (1)
—|/|—Normally closed (NC) contactPasses power when input is OFF (0)
—( )—Output coilEnergised if rung is logically true

Rules for drawing ladder

  1. Read left → right, top → bottom (order of scan).
  2. Each rung starts at left rail with input contacts and ends at right rail with one output.
  3. Outputs (coils) are never placed on the left; contacts never on the right of a coil.
  4. A contact can be used many times; an output address normally only once as a coil.
  5. Every input/output is given an address (X0, Y0…).

Instruction list (mnemonics) – Mitsubishi style

MnemonicMeaningAND rung above
LD / LDIStart rung with NO / NC contactLD X0
AND / ANISeries NO / NC contactAND X1
OR / ORIParallel NO / NC contactOUT Y0
OUTOutput coil

Other logic: NAND = two NC contacts in parallel; NOR = two NC in series; XOR = (A·B̄) + (Ā·B) – two branches.

3.5Latching & Internal Relays

Latching (self-holding) keeps an output ON after the momentary input (push button) is released, by putting a contact of the output itself in parallel with the input.

Fig 6 – Start/Stop latch circuit (motor control)

  • Stop button wired as NC for fail-safe: a broken wire stops the motor.
  • SET / RESET (SET/RST, S/R) instructions do the same job: SET Y0 latches, RST Y0 unlatches.

Internal relays (auxiliary relays / markers / flags)

  • Software bits inside PLC memory (M0, M100… or B3:0) that behave like relays but have no physical output terminal.
  • Used to store intermediate results, build complex logic, start several outputs from one condition, and in latch / sequencing / shift-register programs.
  • Battery-backed (retentive) relays keep their state during power failure — so the process resumes from the same step.

3.6Sequencing

Many machines run actions in a fixed order (e.g., drilling: clamp → drill down → drill up → unclamp). Sequence is controlled using limit switches, internal relays, timers, or a sequencer (drum) instruction.

Example – two pneumatic cylinders A, B: sequence A+ B+ A− B− (+ = extend, − = retract). Limit switches: a0/a1 (A retracted/extended), b0/b1.

Fig 7 – Displacement–step diagram for A+ B+ A− B−

Logic: A+ = Start · a0 · b0  |  B+ = a1  |  A− = b1  |  B− = a0 (after A−). Each step is stored in an internal relay (M1…M4) which is latched and the previous one reset — this avoids two signals conflicting (signal overlap).

3.7Timers & Counters

Timers

  • TON – On-delay timer: output turns ON after preset time once input stays ON. (Most common.)
  • TOF – Off-delay timer: output ON immediately, turns OFF preset time after input goes OFF (e.g., cooling fan runs after motor stops).
  • RTO – Retentive timer: accumulates time over several ON periods; needs a RESET.
  • Pulse timer (TP): gives a fixed-width pulse.
  • Time = Preset (PV/PRE) × time base (10 ms, 100 ms, 1 s). Accumulated value = ACC/ET.

Fig 8 – On-delay timer: ladder + timing diagram

Counters

  • CTU – Up counter: counts rising edges; when count = preset, counter contact closes.
  • CTD – Down counter: counts down from preset to 0.
  • CTUD – Up/down counter (e.g., cars entering/leaving a car park).
  • Always needs a RESET input to bring the count back to zero.

Fig 9 – Up counter: packing 10 items per box

3.8Shift Registers

A shift register is a group of internal relays (usually 8 or 16 bits, e.g., M100–M107) in which each bit's status is moved one place along each time a shift (clock) pulse arrives. Used to track items on a conveyor.

Three inputs: OUT (data in – value entered into first bit), SFT (shift pulse) and RST (clear all bits).

Fig 10 – 8-bit shift register before and after a shift

Application – rejecting faulty bottles: inspection sensor at station 1 puts "1" (faulty) into M100; each bottle movement gives a shift pulse; when the "1" reaches M104 (the reject station) it energises the reject solenoid.

3.9Master Control & Jump Controls

Fig 11 – Left: master control relay (MCR) zone · Right: jump (JMP / LBL)

  • Master control relay (MCR): switches a whole block of rungs on/off together. If the MCR rung is false, all non-retentive outputs inside the zone are turned OFF. Used for emergency/section shutdown. Zone ends with MCR END (MCE).
  • Jump (JMP) & Label (LBL): when the jump condition is true, the PLC skips rungs up to the label. Outputs in the skipped section are held in their last state (not turned off). Saves scan time; used to choose between two program sections (e.g., manual / auto mode).
  • Difference: MCR → outputs OFF · JMP → outputs frozen.

3.10Code Conversion & Data Handling

Code conversion

Field devices often use BCD (thumbwheel switches, 7-segment displays) while the PLC works in binary. PLCs provide BIN (BCD → binary) and BCD (binary → BCD) instructions; also Gray code (from absolute encoders) and ASCII.

DecimalBinaryBCDGray
501010000 01010111
910010000 10011101
1211000001 00101010
590011 10110101 1001—

Worked: 59 → BCD: 5 = 0101, 9 = 1001 ⇒ 0101 1001.   Binary → Gray: Gn = Bn, Gi = Bi+1 ⊕ Bi (e.g., 1100 → 1010). Gray code changes only 1 bit between steps ⇒ no false readings in encoders.

Data handling

PLCs store 16-bit words in data registers (D0, D1…; N7:0). Instructions:

  • Move: MOV / MOVE source → destination (copy a value, e.g., load new timer preset).
  • Compare: EQU (=), NEQ (≠), GRT (>), LES (<), GEQ, LEQ – contact closes if true. E.g., if temperature D0 > 80 then turn heater OFF.
  • Arithmetic: ADD, SUB, MUL, DIV, SQR.
  • Logical: word AND, OR, XOR, NOT; masking bits.
  • Block transfer / FIFO / table functions for recipes & logging; analog inputs read through ADC modules as numbers (0–4095).

3.11Selection of a PLC

  1. Number of I/O points required (+ 20% spare for expansion).
  2. Type of I/O – digital/analog, AC/DC, voltage & current levels, relay vs transistor outputs, special modules (high-speed counter, PID, stepper).
  3. Memory size needed for program & data.
  4. Speed – scan time required by process.
  5. Instruction set / functions – timers, counters, maths, PID, shift registers.
  6. Communication – Ethernet, Modbus, Profibus, HMI/SCADA networking.
  7. Environment – temperature, humidity, vibration, dust, EMI.
  8. Type – compact/fixed (small machines) vs modular/rack (large plants).
  9. Cost, vendor support, software, programming language (IEC 61131-3: LD, FBD, ST, IL, SFC).
Remember the IEC 61131-3 languages as "L-F-S-I-S": Ladder, Function block, Structured text, Instruction list, Sequential function chart.

UNIT – IV

4.1AI Inclusion in Mechatronics

Classic mechatronics = mechanics + electronics + control + computing. Adding Artificial Intelligence makes the system able to perceive, learn, decide and adapt instead of only following fixed rules — "intelligent mechatronic systems".

Fig 12 – Where AI sits inside a mechatronic loop

AI techniques used

  • Machine learning – regression/classification from sensor data.
  • Computer vision (CNN) – object detection, quality inspection, pick-point finding.
  • Fuzzy logic control – rules like "IF temp is high THEN fan is fast" (washing machines, ACs).
  • Neural-network control – learns nonlinear plant models.
  • Reinforcement learning – robot learns by trial & reward.

Applications

  • Predictive maintenance (vibration analysis → predict bearing failure).
  • Autonomous vehicles / AGVs – path planning, obstacle avoidance (SLAM).
  • Smart robots – adaptive gripping, human-robot collaboration.
  • Self-tuning controllers, anomaly/fault detection.
  • Edge AI / TinyML – models running on MCU itself.

Benefits: adaptability, higher accuracy, less downtime, handles uncertainty. Challenges: needs large data, high compute, explainability, safety certification, real-time limits.

4.2Signal Conditioning & Data Acquisition

Signal conditioning = processing the raw sensor output so that it becomes suitable for the next stage (ADC / controller): right level, clean, safe and linear.

Functions of signal conditioning

  1. Protection – against high voltage/current (zener diode, fuse, current-limiting resistor, opto-isolator).
  2. Amplification – mV signals (thermocouple, strain gauge) → volts, using op-amps.
  3. Filtering – remove noise: low-pass, high-pass, band-pass, notch (50 Hz mains).
  4. Conversion – resistance → voltage (Wheatstone bridge), current 4–20 mA → voltage, analog ↔ digital.
  5. Isolation – optical/transformer isolation between sensor and controller.
  6. Linearisation – correct nonlinear sensor output (look-up table/software).

Fig 13 – Inverting op-amp amplifier (most asked signal-conditioning circuit)

Data Acquisition System (DAQ)

DAQ = the process of measuring physical quantities with sensors, conditioning them, converting to digital form and storing/processing them in a computer.

Fig 14 – Data acquisition system

  • Multiplexer – selects one of many sensor channels at a time to share one ADC.
  • Sample & hold – freezes the voltage while ADC converts.
  • ADC types – successive approximation (common), flash (fastest), dual-slope (accurate, slow), sigma-delta.
  • Sampling theorem (Nyquist): fs ≥ 2 fmax – otherwise aliasing. Use an anti-aliasing low-pass filter.
  • Resolution: Δ V = Vref / 2ⁿ   e.g., 10-bit, 5 V ⇒ 5/1024 = 4.88 mV; 12-bit ⇒ 1.22 mV.
  • DAQ board specs: number of channels, sampling rate, resolution, input range, accuracy.

4.3Mechatronic Actuation

An actuator converts a control signal (usually electrical) into physical action — motion or force.
TypeExamplesFeatures
ElectricalDC motor, BLDC, stepper, AC servo, solenoid, relayClean, precise, easy to control electronically
HydraulicCylinders, hydraulic motorsVery high force, used in presses, excavators
PneumaticAir cylinders, grippers, valvesFast, cheap, clean; less accurate (air compressible)

  • Stepper motor – moves in fixed steps (e.g., 1.8° ⇒ 200 steps/rev), open-loop position control. Step angle = 360°/(steps per rev).

4.4Embedded Firmware Architecture

Firmware is the software permanently stored in the non-volatile (Flash) memory of an embedded device that directly controls its hardware. Its architecture is the way that code is organised into layers and modules.

Fig 16 – Layered firmware architecture

Firmware design models

  1. Super loop (bare-metal): init(); while(1){ read(); compute(); write(); } – simple, cheap; but response time depends on loop length, no priorities.
  2. Interrupt-driven (foreground/background): ISRs handle urgent events, main loop does the rest.
  3. RTOS-based: work split into prioritised tasks; scheduler guarantees deadlines – used for complex & safety-critical systems.
  4. Event-driven / state machine: system modelled as states + transitions (good for sequences).

Key parts: bootloader (start-up, firmware update/OTA), HAL (makes code portable across chips), drivers, watchdog timer, memory map (Flash, RAM, stack, heap).

4.5RTOS for Safety-Critical Systems

A Real-Time Operating System (RTOS) is an OS that guarantees a task's response within a fixed, known time (deterministic). Correctness depends on both the logical result and the time at which it is produced.
  • Hard real-time – missing a deadline = system failure (airbag, ABS, pacemaker, flight control).
  • Soft real-time – occasional miss only degrades quality (video streaming).
  • Safety-critical system – failure can cause death, injury or major damage.

Fig 17 – Task states in an RTOS

Key RTOS concepts

  • Task / thread – independent function with its own stack and priority.
  • Pre-emptive priority scheduling – highest-priority ready task always runs. Rate Monotonic: shorter period ⇒ higher priority. EDF: earliest deadline first. Round-robin for equal priority.
  • Inter-task communication – queues, mailboxes, event flags.
  • Semaphore & mutex – protect shared resources (critical sections).
  • Priority inversion – high task waits for a resource held by a low task while a medium task runs (Mars Pathfinder 1997 bug). Fix: priority inheritance / priority ceiling.
  • Low interrupt latency & context-switch time, small memory footprint.

Safety features needed

  • Determinism & bounded worst-case execution time (WCET).
  • Watchdog timer – resets system if software hangs.
  • Memory protection (MPU) – one task can't corrupt another.
  • Spatial & temporal partitioning (ARINC 653).
  • Redundancy, fail-safe states, error detection (CRC, ECC).
  • Certified to standards: IEC 61508 (SIL 1–4, industrial), ISO 26262 (ASIL A–D, cars), DO-178C (aircraft), IEC 62304 (medical).
  • Examples: FreeRTOS / SafeRTOS, VxWorks, QNX, INTEGRITY, Zephyr.
GPOS vs RTOS: GPOS (Windows/Linux) maximises throughput & fairness; RTOS maximises predictability. Write this line in every RTOS answer.

4.6Building Physics-Accurate CAD Models in Simulation

Before building hardware, mechatronic engineers create a virtual prototype — a CAD model that also has correct physics (mass, inertia, friction, joints, motor limits) — and test controllers on it in a simulator. When it stays linked to the real machine with live data it becomes a digital twin.

Fig 18 – Workflow: CAD → physics model → simulation → validation

  • Accurate parameters: density/material, centre of gravity, moments of inertia, stiffness, gear ratios, motor torque–speed curves, sensor noise.
  • Physics engines: ODE, Bullet, MuJoCo, PhysX; tools – MATLAB Simulink/Simscape Multibody, Gazebo/ROS, CoppeliaSim, MSC Adams, ANSYS (FEA/CFD).
  • Co-simulation: mechanical model + electrical model + control software together (Model-in-the-loop → Software-in-the-loop → Hardware-in-the-loop).
  • Benefits: fewer physical prototypes, lower cost & time, safe testing of failures, controller tuning, training data for AI (sim-to-real).
  • Limits: model only as good as its parameters ("reality gap"), heavy computation.

4.7Designing Mechatronic Systems

Stages of the design process

  1. Need – customer/market need identified.
  2. Analysis of the problem – understand true problem.
  3. Specification – requirements: functions, loads, speed, accuracy, cost, size.
  4. Conceptual design / possible solutions – generate alternatives (mech vs electronic solution).
  5. Selection of best solution (evaluation matrix).
  6. Detailed design – components, circuits, software.
  7. Prototype, test & modify, then production & working drawings.

Fig 19 – V-model for mechatronic design (VDI 2206)

Traditional designMechatronic design
Sequential – mechanical first, then electrical, then control addedConcurrent / integrated – all domains designed together
Functions done mechanically (cams, gears, linkages)Functions moved to electronics & software (MCU, PLC)
Rigid, hard to changeFlexible – change by reprogramming
Bulky, more parts, more wearCompact, fewer moving parts, more reliable

Example of the change: mechanical cam-timer in washing machine → MCU program; mechanical carburettor → electronic fuel injection; analogue bathroom scale (springs/rack) → load-cell + MCU digital scale.

4.8Case Studies of Mechatronic Systems

(a) Pick-and-place robot

Picks an object from one position and places it at another (assembly lines, packaging, PCB component placement). Typical 3-axis design: base rotation, arm extension, vertical motion + gripper.

Fig 20 – Pick-and-place robot

  • Actuators: pneumatic cylinders (linear moves, cheap, fast) + stepper/servo for rotation; gripper by solenoid valve or vacuum suction.
  • Sensors: limit switches / reed switches at cylinder ends, proximity sensor to detect part, encoder for angle, vision camera (AI) for random part positions.
  • Controller: PLC or MCU running a sequence: detect part → arm out → Z down → grip → Z up → rotate → Z down → release → return.
  • Benefits: speed, repeatability, works 24×7, removes humans from hazardous jobs.

(b) Automated Guided Vehicle (AGV)

A driverless, battery-powered vehicle that carries material in factories/warehouses along a guided path.

Fig 21 – AGV, top view (differential drive)

  • Navigation/guidance: wire-guided (inductive), magnetic tape, optical line following, laser reflector triangulation, vision/SLAM (natural navigation, AI).
  • Sensors: line/magnetic sensors, wheel encoders (odometry), LiDAR, ultrasonic, bumpers, RFID tags for stations.
  • Drive: differential drive — v = (vR+vL)/2   ω = (vR−vL)/L
  • Controller: path following (PID on line error), obstacle avoidance, traffic management by central computer via Wi-Fi, auto battery charging.
  • Safety: emergency stop, bumper, LiDAR safety fields, warning lights & buzzer.

(c) Automatic car park barrier

Barrier rises when the correct coin/ticket/RFID is detected and lowers after the car has passed.

Fig 22 – Car park barrier: layout and PLC ladder program

  • Inputs: X0 coin/ticket accepted, X1 barrier-up limit switch, X2 car-passed sensor (inductive loop / IR beam), X3 barrier-down limit switch.
  • Outputs: Y0 motor raise, Y1 motor lower (or a pneumatic/hydraulic cylinder via solenoid valves).
  • Working: coin → Y0 latches → barrier rises until X1 opens; car passes X2 → Y1 → barrier lowers until X3. Interlocks stop both directions being ON together. A timer can lower it automatically after, e.g., 10 s.
  • Extensions: counter for free spaces (CTUD), "FULL" sign, ANPR camera (AI number-plate recognition), RFID/FASTag.

(d) Engine management system (EMS)

Electronic control of a car engine by an ECU (Engine Control Unit) to get the best power, fuel economy and lowest emissions.

Fig 23 – Engine management system

  • Fuel control: ECU computes injector pulse width from engine speed (crank sensor) and air mass (MAF/MAP); corrected by coolant temp, throttle and O₂ sensor feedback to keep air–fuel ratio at stoichiometric 14.7 : 1 (λ = 1) for the catalytic converter.
  • Ignition control: spark timing (advance) from 3-D map of speed & load; retarded if knock sensor detects detonation.
  • Idle speed, EGR, variable valve timing, OBD-II diagnostics (fault codes, check-engine lamp).
  • Advantages over carburettor: better mileage, lower emissions (BS-VI), smooth start in cold, self-diagnosis.
Case-study answers = labelled diagram + inputs (sensors) + outputs (actuators) + controller + working sequence + advantages. That's the full-marks format.
